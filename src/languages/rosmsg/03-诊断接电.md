# 03 — 诊断接电(RE 批次,2026-09-30)

> 背景:用户实测四点(rosmsg 同包裸字段有支持却报"未知消息类型";启动瞬间输出通道刷屏;xacro 悬浮注释多行/缩进失真;询问裸 `.launch` 是否支持)。本文是 RE 批次事实源(①②④ 的修缮落点在 rosmsg 与 xacro 模块,③ 为纯勘误)。

## 1. 四点调查结论

### ① rosmsg 诊断误报"未知消息类型"(主修,RE-1)

- 判定点:`ui/diagnostic-provider.ts` `analyzeDocument`——非内置类型按 `namesOf(pkg)` 查**内存索引**点查,无任何兜底;裸名只查 selfPkg(语义正确);
- **时序根因**:诊断在 `onDidOpenTextDocument` + 注册时全量初始分析;而 `MessageIndex.initialize()` 在 providers.ts 是 `void` fire-and-forget(工作区全量 walk 秒级 + 系统 `ros2 interface list` 数秒且受 envAvailable 门控)。打开瞬间索引为空 → 同包裸字段(`Pose`)与系统包类型(`builtin_interfaces/Time`)双双判"未知";
- **更关键**:索引就绪/刷新后诊断**不重算**(`analyzeDocument` 只有 analyze 一个调用方;system/workspace 刷新链只刷索引)→ 警告挂到用户手动编辑为止;
- 对照:hover/跳转链路(`findMessageDefinitions`)有三级兜底(工作区正表 → `findMessageWithSystemPath` 系统懒登记 → `resolvePackageDir` 标准布局 FS 点查),故"有支持"。

**修复设计(三级判定 + 重算)**:
1. `analyzeDocument` 改 async;`known` 判定:① `namesOf(pkg)`(原样)→ ② `await index.findMessageWithSystemPath(pkg, name)`(与跳转同源,触发系统包懒登记)→ ③ 标准布局 FS 点查:`packages.resolvePackageDir(pkg)` + `<dir>/(msg|srv|action)/<Name>.<ext>` existsSync,扩展名按当前文档种类(.msg→msg/.srv→srv/.action→action);
2. 裸名:`namesOf(selfPkg)` → FS 点查 selfPkg(ROS"同包省略包名"语义不变);
3. 重算时机:`providers.ts` 中 `index.initialize()` 完成后 + system/workspace 刷新事件(防抖 1s)调用新导出 `reanalyzeAll()`(对打开的 rosmsg 文档重跑分析)——旧警告自动清除;
4. `registerRosMessageDiagnostics` 增 `packages: PackageMap` 参数。

### ② 启动刷屏(日志保留,聚合防重)

`analyze` 对 `scheme!=='file'` 先 `log.debug("分析被跳过(非真实文件)")` 再 return——**这是设计使然**(本文件头注明的"debug:被过滤跳过的场景"约定),保留不删。刷屏来源:Chat 编辑会话为工作集每个文件建快照模型(scheme=`chat-editing-snapshot-text-model`,继承 rosmsg languageId),几十个快照各过一次门。

**处置(用户裁定:设计日志不删)**:同 scheme **首次**照常 debug(文案注明"同类后续跳过见 trace"),同会话内同 scheme 后续跳过降为 `log.trace`——设计可见性保留,重复噪音消失。

### ③ 裸 `.launch` 是否支持(勘误,RE-3,不改产品代码)

**已支持,无缺陷**:
- 语言绑定:package.json `contributes.languages` 的 xml 条目 `"extensions": ["launch", "srdf", "test", "urdf", "xacro"]`(**无点形式有效**)——VS Code 源码 `editor/common/services/languagesAssociations.ts` 的扩展名匹配是 `endsWithIgnoreCase(filename, extension)`,裸 `demo.launch` 以 "launch" 结尾 → 绑定 xml → 内建 xml 语法高亮生效;
- 提供器:launch/ui 三处注册(链接/补全/跳转)与悬浮的 selector 均含 `**/*.launch` 纯 pattern;
- **勘误**:LD-3 记录断言"VS Code 默认不给 .launch 裸后缀指派 xml 语言、双条件下链接永不出现"——归因有误(当日基于猜测未实证);LD-3 的纯 pattern 化保留(对无语言绑定场景更稳),但记录需更正。本轮补宿主集成测试(languageId==='xml')把结论从源码推断升级为实证。

### ④ xacro 悬浮注释多行/缩进失真(RE-2,用户裁定 verbatim)

`extractLeadingComment`(hover-provider.ts:254)与 `adjacentCommentAbove`(completion-provider.ts:951)双实现同构:每行整行 trim(相对缩进丢失)+ 块内空行折叠 + blockquote 渲染(markdown 再折叠行首空格)。

**用户裁定**:`<!-- -->` 内部内容 **verbatim 显示(换行和空格都保留),外壳不管**。实施:内文仅去 `\r`、最多剥掉紧跟 `<!--` 的一个换行与 `-->` 前的一个换行(外壳放置痕迹),不 trim、不去缩进、不折叠空行;渲染改围栏代码块(无语言);双实现同源化(共用一处导出)。

## 3. 边界

- 诊断三级判定不引入新索引/新扫描:②复用 RM-1 懒登记(单飞缓存),③是 existsSync 点查(仅索引未命中时逐字段触发,且 resolvePackageDir 有缓存);
- FS 点查只认标准布局 `msg|srv|action` 子目录(与 colcon 安装语义一致),非标准布局仍报未知(与跳转兜底同口径);
- xacro 注释锚定规则(结束行==defLine-1、紧邻非空、只取一块)不变;多块堆叠合并不在本轮(用户未要求)。
