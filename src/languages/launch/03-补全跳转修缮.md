## 3. 取证结论(LD-1)

**取证①(launch.py 双定义)**:
- 我方 `LaunchDefinitionProvider` 代码路径至多返回一个 Location(pyDefinition 三分支互斥早退;注册唯一);
- 仓内其余 DefinitionProvider 选择器均不覆盖 `.launch.py`:rosmsg=语言 `rosmsg`,xacro=`**/*.xacro|**/*.urdf`;
- → 第二定义来自外部 Python 语言服务(Pylance)与**我方肥 include range 的重叠**(join 案 range 罩住
  `os.path.join(launch_dir, …)` 全段,`launch_dir` 变量同时被 Pylance 解析——与用户点 3 自述互证)。
- 处置:LD-4 窄化为主修(变量段退出我方 range);`package=`/`executable=` 纯字符串值位 Pylance 通常无返回,
  修复后应回归单一定义。peek 二列残口(若 Pylance 对值位仍有返回)最终口径报用户裁定。

**取证②(exec 名碎裂)**:
- VM 日志证实索引名=完整 `py_listener.py`(跳转 `p10_mix_deps_std/py_listener.py` 命中);
- VS Code 官方 python 语言配置(microsoft/vscode extensions/python/language-configuration.json)**未定义
  wordPattern** → 默认词模式把 `.` 当分隔 → `py_listener.py` 天然是 `py_listener`+`py` 两个词,宿主
  词级建议按词供候选 → 列表出现碎片。
- 处置:provider 侧无法关宿主词建议(`editor.wordBasedSuggestions` 是用户设置);LD-6 以我方项全值
  range + 置顶 sort + rich detail 凭信息量胜出;名单本身无需修改。
