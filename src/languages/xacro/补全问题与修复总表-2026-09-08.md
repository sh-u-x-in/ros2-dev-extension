## 0. 机制速览(先记住这几个"参数",后面所有问题都归到它们头上)

| 机制字段 | 职责 | 本模块结论 |
|:--|:--|:--|
| `filterText` | 命中匹配文本;不设则默认用 `label` | 静态片段显式设置;动态三类默认 label |
| `label` | 列表主文本 | 同前缀片段带 `(中文)` 后缀消歧;中文不进 filterText |
| `detail` | 行右侧小灰字 | 变量项示 `${name}` 形态等 |
| `documentation` | 选中后的详述面板 | property/arg 附"定义行+上方注释";形参不附 |
| `sortText` | 排序档 | `3_attr < 4_jointType < 5_var < 6_sub < 7_file` |
| `insertText` | 接受后实际插入 | 可与 label 不同;元素片段按上下文去头 `<` |
| `range` | 替换范围;不设 = VS Code 按当前词 | 与"多出一个 `<`"直接相关 |
| triggerCharacters | 敲下即唤起提供器的字符 | 现注册 `"<"` `"{"` `"("` `"/"`,均窄用途门控 |
| quick suggestions | 词字符自动触发(Invoke) | 字母路径不受门控 |
| word-based suggestions | VS Code 内置整文件相似词 | 非本扩展;曾在 `$(` 处造成"有弹出但非我们"的错觉 |

## 4. 给其他 AI 的示范(launch/rosmsg 等模块改造可复用这套做法)

本表本身就是一份"问题闭环模板",改 launch/rosmsg 时照此办理:

### 4.1 记录纪律(改完必补,缺一不可)

- **每笔修复 → 所在子目录 README 补一行,精确到分钟**(YYYY-MM-DD HH:mm):改 ui 记 `ui/README.md`、改 core 记 `core/README.md`、模块级里程碑记模块根 `README.md`;
- **总表 §1**:一行=现象(用户原话)→ 机制层根因 → 处置 → 涉及文件;§2 记录行与 README 分钟一一对应;§3 把"决策不做/搁置"也写清(避免后人重复论证);
- 收尾固定 `;tsc 0 错误`;交付附 **dev-build + Reload 复验清单**(dist 与 src 分离,不重建=改了等于没改)。

### 4.2 方法论(本会话反复验证有效)

1. 现象先别猜,读代码定位**机制层字段/事件源**——典型四类:
   - 匹配不进 = `filterText`/子序列(问题 #1);
   - 不自动弹 = triggerCharacters 没登记、或弹出的是 word-based suggestions(非你的表)(#2/#6);
   - 要保存才更新 = 索引/图吃 **FileSystemWatcher(磁盘)**,没吃 `onDidChangeTextDocument` 活文本(#18);
   - 跳转/链接异常 = 目标没做"是否普通文件/分隔符归一"护栏(#17);
2. **修复只落单模块**,并明说"launch/cpp/py 同款未动,待验证后统一"(每处改动加日期注释);
3. 每改必 `tsc`;切分/纯函数逻辑用 node 复刻冒烟(列真实样例 + 负例);
4. 先"只查证不改"、再问"要不要做",用户批准才动(本会话多次被提醒:没说改就别改);
5. 能嵌进既有机制就不新建(如 `$(arg)` 跳转复用 `findSymbol`/名称锚点,加的是"引用形态扫描器"不是新架构)。
