# 环境变量获取机制与数据来源路线调查

> 状态：调查结论（2026-09-01）
> 目的：为 config/gen/intellisense-config.ts 的 `getSystemIncludeDirs()` / extraPaths / `.clangd` 数据来源提供依据
> 方法：读源码（ros2/environment/*、extension.ts 注入点、rde-common sourceSetupFile、compile-commands）+ 对照外部调研（gen/外部调研-ROS2路径映射与intellisense-参考）

---

## 1. 结论先行

- **环境变量获取已有成熟管线**：扩展启动时执行 ROS setup 脚本并 dump 环境，结果存内存（`environmentFacade.getEnv()`），带缓存（mtime + 配置快照）与变化事件（`onEnvChanged`）。**无需另起炉灶**。
- **intellisense-config 的系统 include 已接这条线**（extension.ts 注入 `getSystemIncludeDirs`：取 env 的 CMAKE/AMENT_PREFIX_PATH → 拼 /include 检测存在）。
- **但有四处缺口（均为 intellisense-config.ts 现有实现）**：① extraPaths 没用 env.PYTHONPATH（现为扫 setup.py 目录，漏 PYTHONPATH 注入的构建/非工作区目录，如 build/<pkg>）；② 订阅只挂 packageCore.onDidChange，**没挂 onEnvChanged**（环境变了系统 include 不刷新）；③ `.clangd` 的 -I 未展开到 include/<pkg>/ 子层、缺 -std=c++20（外部调研参考第 6 节）；④ 系统 include 前缀源未含 COLCON_PREFIX_PATH（仅 CMAKE/AMENT_PREFIX_PATH）。

---

## 2. 现有获取管线（已实现，主路线）

### 2.1 执行层：rde-common `sourceSetupFile`（node_modules/@ranchhandrobotics/rde-common/dist/utils/process.js）

| 平台 | 机制 | 环境 dump 方式 |
|---|---|---|
| Windows | 临时 .bat：vcvarsall（VS 控制台）→ pixi shell-hook → `call "<setup>"` → `set` | 解析 `set` 输出的 `KEY=VALUE` 行 |
| 非 Windows | `<shell> --login -c "source '<setup>' && env"`（bash/zsh/sh 走 login shell） | 解析 `env` 输出的 `KEY=VALUE` 行 |

- 约束：60s 超时、1MB buffer、`child_process.exec`；解析规则 = 首个 `=` 分割、跳过空键/含空格键。
- Windows 下 ROS setup 为 `C:\opt\ros\<distro>\x64\setup.bat`（source.ts 构造）；Linux 为 `/opt/ros/<distro>/setup.sh`。

### 2.2 缓存与事件层：src/ros2/environment/

| 模块 | 职责 |
|---|---|
| `source.ts` | `refreshSystemEnv()`：配置脚本(ROS2.env.setupScript)→ 自动发现发行版(/opt/ros 扫描 + getDistros)→ 系统层缓存(systemEnvCache：来源文件 mtime + distro/env.setupScript/env.pixiRoot 配置快照失效)；`sourceWorkspaceOverlay()`：叠加 `<ws>/install/setup.*`（overlay mtime 预检，未变跳过） |
| `state.ts` | `getEnv()` 读当前 env；`getEnvIssue()` 可用性（ROS_DISTRO 已知发行版 + ROS_VERSION=2）；`onEnvChanged` 事件 |
| `register.ts` | 监听 bashrc 等（1.5s 防抖失效缓存）、`install/**`（1s 防抖 → 刷新 overlay + 合并 compile_commands）、env 相关配置变化 |
| `activate.ts` | 完整激活：source → context key → 环境组件重装配；`refreshOverlayAfterBuild` 供 install watcher 驱动 |

- env 含 57~59 个变量（系统层 + overlay 两段 source 的差即 COLCON_PREFIX_PATH 等 overlay 新增）。

## 3. 可行的数据来源路线对比

| 路线 | 数据 | 优点 | 局限 | 结论 |
|---|---|---|---|---|
| **A. environmentFacade.getEnv()**（内存 env） | AMENT_PREFIX_PATH / CMAKE_PREFIX_PATH / PYTHONPATH / COLCON_PREFIX_PATH / ROS_* 全量 | 零额外开销；与运行时一致（已含 overlay）；有缓存+事件 | 依赖 source 成功（getEnvIssue 可判）；未 source 时为 undefined | ✅ **主路线（已用）** |
| **B. process.env**（宿主进程环境） | 扩展进程启动时环境 | 零成本 | VS Code 进程环境固定，不含 source 结果；仅终端启动 code 时才碰巧有 | ⚠️ 兜底（source.ts 已用作 fallback：`else if (process.env.ROS_DISTRO) newEnv = process.env`） |
| **C. 终端集成**（vscode.ShellIntegration / terminal.integrated.env） | 终端实际环境 | 用户手动 source 过的终端也能拿到 | 需 shell integration 激活、异步；环境可被用户污染 | ⚠️ 不推荐作为系统 include 来源（terminal-profile 只用 getEnv()，未走此路） |
| **D. compile_commands.json**（`build/<pkg>/compile_commands.json` 合并） | 每条编译命令的真实 -I/-std | clangd 最权威（CompilationDatabase: build）；已由 `mergeCompileCommands` 维护（install/** watcher 驱动） | 需先构建才有数据；未构建为空 | ✅ **C++ 侧平行路线（与 -I 互补）** |
| **E. 静态解析 setup 脚本产物**（install/setup.bash / _local_setup_util） | 变量赋值 | 不执行脚本 | colcon 生成物靠 python 计算，静态读不可靠 | ❌ 不采用 |

## 4. 与 intellisense-config 的对接现状与缺口

### 4.1 现状（extension.ts 注入 `getSystemIncludeDirs`）

```ts
const env = environmentFacade.getEnv();
// 取 CMAKE_PREFIX_PATH + AMENT_PREFIX_PATH → 拼 /include → fsPromises.access 检测存在
```

- 已覆盖：系统 include 顶层目录（c_cpp_properties 的 `/**` 语义下够用，外部调研参考第 5 节）。

### 4.2 缺口

| # | 缺口 | 影响 | 建议 |
|---|---|---|---|
| 1 | extraPaths 未用 env.PYTHONPATH（现只扫含 setup.py 的目录） | 漏收 PYTHONPATH 注入的构建目录（如 build/<pkg>）与第三方/系统 python 包路径 | PYTHONPATH 原样并入 extraPaths（以环境变量为准，不感知构建模式），工作区目录扫描保留 |
| 2 | 订阅只挂 packageCore.onDidChange，未挂 onEnvChanged | 环境 source/变化后系统 include 不自动刷新 | `subscribe(onDidChangeEnv)` → 重算 include |
| 3 | `.clangd` -I 未展开 include/<pkg>/ 子层、缺 -std=c++20 | 双层 include 的 ROS 系统头解析不到（外部调研参考 5/6 节） | .clangd 生成时逐层展开（对齐 gen_clangd_include.sh）+ 固定 -std=c++20；或引导 `CompilationDatabase: build`（路线 D） |
| 4 | 前缀源未含 COLCON_PREFIX_PATH | 某些 colcon overlay 布局缺 include | 并入前缀集合（terminal-profile 已用该键） |
