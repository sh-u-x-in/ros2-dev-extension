## 2. 各新功能实现方案

### 2.1 新功能 01 一键配置（关联度最高，写侧主战场）

**目标**：右键文件 → 一步改写构建文件（package.xml / CMakeLists.txt / setup.py），接入包的构建/安装体系（设计文档 01 语义 A 已敲定）。

**可复用（读侧）**：
- `parse/setup-parser.ts` + `parse/cmake-parser.ts`：解析现有内容，做**幂等判定**（"是否已配置"），避免重复追加；
- `derive/executable-map.ts`：判断包是否参与构建、包内已有可执行入口；
- `derive/event-collector.ts` 的 watcher：写回 → 自动触发增量刷新，天然闭环（设计总纲约束 2"复用现有监听刷新"，无需新增定时器）；
- package-core `ingestPackageCreated`：新建包场景接入。

**缺口（全新建，落位 `write/configure-file.ts`）**：

| 文件类型 | 写回动作 |
|---|---|
| launch（`*.launch.py/xml`） | ament_cmake：`install(DIRECTORY launch ...)`；ament_python：`data_files` 补 launch 项 |
| msg/srv/action | `rosidl_generate_interfaces(...)` + `find_package(rosidl_default_generators)` + package.xml 依赖链 |
| python 可执行 | `console_scripts` 或 `install(PROGRAMS)`，加可执行权限 |
| shell 可执行 | `install(PROGRAMS ...)` + `chmod +x` |
| C++ 文件 | `add_executable` 骨架 + `ament_target_dependencies`（含依赖探测） |

**流程**：按扩展名 + 包内相对位置识别文件角色 → `findPackageForPath` 定位包 → parse 现有内容 → diff（已有 vs 需要）→ 追加缺失片段 → 写回 → 依赖现有 watcher 自动刷新。

**待定问题（需在设计期敲定）**：
1. 写构建文件安全性：直接写 vs 预览确认（diff）vs 生成片段自贴；是否备份/undo（设计总纲约束 5：写前必确认）；
2. 依赖探测深度：`#include <rclcpp/rclcpp.hpp>` → 自动加 `rclcpp` 依赖？是否超范围；
3. 菜单组织：固定一个"一键配置" vs 按文件类型显示多个。

**建议**：先补 cmake-parser 单测（写回正确性依赖它）→ 按"解析→diff→追加→写回"逐文件类型落地（launch/msg → python/shell → cpp）。

### 2.2 新功能 02 工作包重命名（关联度高，但被接线缺口阻塞）

**目标**：文件夹名 ≠ 包内声明名时弹选项，程序接管重命名，以文件夹名称为准（设计文档 02）。

**可复用**：
- `derive/executable-map.ts` 的 `checkNameMismatch` 三方校验（目录名 / package.xml / 配置内名）+ `onNameMismatch` 事件出口 + `derive/types.ts` 的 `NameMismatchEvent`；
- parse 模块可读 `project()` / `name`，用于改写前的现状读取。

**缺口（落位 `write/package-rename.ts` + 命令层）**：
- `detectNameMismatch(dir)`：读 package.xml / CMakeLists.txt / setup.py，比对文件夹名（事件源已由 executable-map 提供）；
- `promptRenameStrategy(dir)`：QuickPick 三选（以文件夹名为准 / 以声明名为准 / 忽略）；
- `applyRename(dir, strategy)`：程序接管改写；**写回时标记来源抑制自触发**（避免 watcher 循环弹窗）；
- 联动范围（待定）：Python 包目录、`include/<pkg>/`、`setup.py` 的 `package_name`/data_files、跨包 `<depend>` 引用、launch/代码硬编码包名（建议只提示不改）；
- 忽略记忆：仅会话 / 该目录长期记住 / 全部（待定）；
- 失败回滚：文件被占用等中途失败的提示与回滚。

**🔴 阻塞点**：executable-map 未接线 → `onNameMismatch` 永远不会触发。**接线是本功能第一前置任务**。

**建议**：接线 → detect/prompt/apply 三步 → 先只改必改两项（package.xml + CMakeLists `project()`，即设计文档 02 风险提示的底线），再谈联动。

### 2.3 新功能 03 一键启动（关联度中，数据源已备）

**目标**：右键文件一步启动（launch / python / shell / C++），自动定位包 + 环境 source。

**可复用**：
- `derive/executable-map.ts` 的 `PackageExecutables`：包 → consoleScript/cmakeTarget/exportExecutable 入口映射，用于"按入口运行"与 C++ 产物名确定；
- `build/` 现有 colcon 构建命令、`commands/terminal.ts`（createTerminal）、`activateEnvironment`（环境 source 前置）。

**缺口（落位命令层 `quick-run`，config 外）**：
- `runFile(uri)`：按扩展名分发 launch / script / cpp 三路；
- 每路先 `findPackageForPath` 定位包 → 环境 source → 执行；
- launch：复用 `ROS2.launch`（`commands/core.ts`）或 launch-tree run；
- script：`python3` / `bash`（或 `./` 若可执行）；
- cpp：`ColconBuild` → 提示运行产物（产物名读 `add_executable` 目标名，即 executable-map 数据）。

**⚠️ 邻接依赖**：设计文档 05 决策**删除 launch 树**（含 dumper，任务 #1 尚未执行）——launch 一键启动的底座需重新评估（复用 `ROS2.launch` vs 等 launch 静态能力重建后再定）。

**待定**：C++ "编译+运行"连做还是仅编译（待定项 1）；环境 source 策略（每键必 source vs 新终端注入）；终端通道（复用 vs 新开）；是否提供调试入口。

**建议**：数据源前置与 02 相同（接线 executable-map）→ script/launch 两路先行（复用现有命令）→ C++ 路依赖 executable-map 目标名。

### 2.4 新功能 04 包创建依赖多选（关联度低，基本独立）

- 与 config 无直接关系；落位 `create/`（`create-package-command.ts` 的 `inputDeps` + `dep-parse.ts` 已有去重/校验）+ `rosApi.getPackageNames()` 候选源（设计文档 README 已核）；
- 可顺带复用 package-core `ingestPackageCreated` 接入新建包；
- 可与 01/02/03 并行，不依赖本模块。

## 4. 建议实施顺序（依赖驱动）

```
第 1 步（地基收尾）：extension.ts 接线 executable-map + event-collector；补 cmake-parser 单测
   ↓ 服务于 01/02/03 三功能
第 2 步：01 一键配置（write/configure-file.ts，按 launch/msg → python/shell → cpp 分步）

第 4 步：03 一键启动（quick-run，script/launch 先行，C++ 依赖 01 的 add_executable 骨架）
第 5 步：04 依赖多选（独立，可与 2-4 并行）
```
