> 状态：**设计稿（待评审）**（2026-09-01）

## 1. 目标与边界

### 目标

1. 依赖候选 = **工作区已确认包 ∪ 环境可见包**（2026-09-14 修订；原"只含已安装系统包"硬约束**反转**，见 §3），两侧来源都已在列表里挑，拼写错误问题归零；
2. 保留**自定义输入**（列表外依赖兜底），按用户指定规则触发：勾选「自定义输入」才弹输入框，不勾不弹；
3. 合并结果照常走现有 `dep-parse` 校验/去重后写入生成器。

### 非目标（首版不做）

- ~~**不叠加工作区 src/ 包**：叠加会诱导误用（把未 build 的包写进去）~~ → **2026-09-14 反转：工作区包按并集进候选**。理由：① 工作区侧名称来自 package-core `unignored`（colcon list 权威 + walk 兜底），**已通过合法性检查**，只是可能尚未构建——与「自定义输入」（允许任意列表外名字，只查格式）相比要求严格得多，排除它没有依据；② `system` 域语义已改为"**只表示工作空间以外**"，不再保证包含本工作空间已构建的包 → 只用 system 取候选**会漏包**，并集是修复而非增强。cmake 类型工作区包的去留见 §10 第 6 条。
- **不分构建/运行依赖两组**：现有 `<depend>` 语义合一、生成器自动展开为 build/build_export/exec 三标签，分组是过度设计；元信息放 QuickPick description 即可。
- **不做后台预取**：候选惰性获取（弹窗时才取）；PackageMap 已缓存即零成本，首次未缓存接受一次 `ros2 pkg list` 延迟（<1s 量级）。
- **不统一一键配置抽象**：仅预留纯函数接口，便于未来复用。

## 2. 交互流程（定稿）

```
inputDeps(kind):
  1. 取候选列表(2026-09-14 并集修订: **工作区 ∪ 环境**, 详见 §3)
     unionCandidateNames(packageCore.getState().unignored, system)
       - 工作区侧 unignored: 含未构建包(名称已过合法性检查); null(未刷新) → 工作区侧缺席
       - 环境侧 system:     [e...] 直接用(容忍 ≤60s 陈旧) / [] 环境侧空 / null → 现跑 pkg_list({})
       - 两侧都拿不到 → 降级纯输入框(现状, 零回归)
  2. QuickPick(canPickMany: true, matchOnDescription: true)
     items = [
        { label: "自定义输入...", description: "勾选后手输不在列表中的依赖名", alwaysShow: true },  ← 固定首位
        ...候选(工作区已确认包在前、环境可见包在后; 内置依赖自动隐藏):
           { label: 包名, description: 元信息标注(纯文本), detail: 来源/语言标注([本工作区包]/[纯 Python 包]/…) }
     ]
     - Esc → 终止流程(与包名/节点一致)
  3. 勾选含「自定义输入」?
       是 → showInputBox(validateInput=validateDepList, 内联校验) → 自定义串; 取消(Esc) → 终止
       否 → 跳过
  4. 合并去重: 勾选项 ∪ parseDepList(自定义)
       与 DEP_BUILTIN 内置重复 → 静默过滤; 勾选与自定义重复 → 静默去重
  5. 显式校验(逐项 validateDepList(kind))
       命中升级/跨体系 → showErrorMessage(具体依赖 + 原因) → 重开 QuickPick(保留上次勾选); 再取消 → 终止
  6. 返回最终依赖数组 → 生成器(现有写入路径不变)
```

### 关键决策点

| 决策 | 结论 | 理由 |
|---|---|---|
| 校验模式 | **内联 → 显式** | 多选场景无输入框承载 validateInput；合并后逐项显式校验，失败弹错重开 |
| 「自定义输入」项 | 固定首位 + **`alwaysShow: true`** | canSelectMany 自带过滤框，不打字时首项会被过滤掉，勾选入口消失 |
| 元信息标注 | QuickPick description 预标注，**多选阶段不拦截** | 勾选是"收集候选"，频繁打断体验差；最终显式校验兜底 |
| Esc 语义 | **一律终止**（多选/自定义输入框/依赖框） | 与包名/节点弹窗统一（2026-09-01 起依赖框已改终止） |
| 重开策略 | 显式校验失败 → 弹错后重开多选（保留上次勾选） | 减少重复勾选成本 |

## 3. 数据源设计

| 层 | 来源 | 说明 |
|:--|:--|:--|
| 工作区侧 | **package-core unignored 域**（`packageCore.getState().unignored`） | **含未构建包**（名称已过合法性检查；colcon list 权威 + walk 兜底）；同时是来源/语言标注的权威表（buildType） |
| 环境侧（首选） | **package-core system 域**（`packageCore.getState().system`） | 已缓存快照 + 分域事件；create 已 B1 直连 package-core（`ingestPackageCreated`），不新增取数路径；**语义 = 只表示工作空间以外**（不再兜底工作区包） |
| 环境侧（回退） | `ros2ServiceApi.pkg_list({})`（**现跑**） | ros2 执行口，`src/ros2/registry/ros-cli.ts` 的包选择 QuickPick 同源；绕过缓存时序，环境合法必然非空 |
| 合并 | `unionCandidateNames(unignored, system)`（纯函数） | 按名去重，**工作区在前**；同名以工作区为准（运行时 overlay 同为工作区胜出） |
| 降级 | 两侧都拿不到 → 纯输入框 | `unignored` 未刷新 **且** system 现跑失败；任一侧有数据即不降级（2026-09-14 起） |

**刷新机制（2026-09-01 已核实源码）**：
- package-core 的 system 域**只在 `rebuild` 时刷新**（`data/index.ts:203` 注释：仅 rebuild（定时器/强制）时顺带刷新，文件变化懒重建不刷）；rebuild 只由 `timer-tick`（缺省 60s）触发——**`forceRefresh()` 是 "refresh" 模式，不刷新 system 域**（救不了冷启动空窗）；
- package-core **未订阅环境 re-source 事件**（`onDidChangeEnv` 只挂在 extension.ts 与 PackageMap；package-core 的 event 层仅 fs-watcher + timer）→ 环境 re-source 后 system 域**最多延迟 60s** 更新；
- **加载顺序推演**（证明"空"是常态可达状态，非极低概率）：`createPackageCore` 构造时仅 `forceRefresh()`（refresh 模式）→ system 恒空；首载后 **60s 内 system 必为空**；此后每 60s timer-tick 才刷新一次。另：create 命令**无环境门控**（用户随时可创建）→ 环境就绪前的创建必然拿到空缓存；
- **取数策略（定稿, 2026-09-01 五域 null 契约；2026-09-14 并集修订）**：弹窗时读 `getState()`——
  - **工作区侧**：`unignored` 非 null → 全部进入候选（含未构建包）；null（未刷新/未知）→ 工作区侧缺席，**不阻塞环境侧**；
  - **环境侧**：system `null`（**未刷新/未知**, 冷启动或从未成功获取）→ 直接现跑 `ros2ServiceApi.pkg_list({})`（绕开缓存时序）;
    system `[]`（**已刷新但确实没有**外部包）→ 环境侧为空, 不再现跑; system `[e...]` → 直接用（容忍 ≤60s 陈旧）。
  - **不降级条件**：并集非空即正常多选（任一侧有数据即可）；只有两侧都拿不到候选才退纯输入框。
  - **不要用 forceRefresh 补 system**（refresh 模式不刷 system 域, 无效）。
- **"空"为何可达（2026-09-01 定稿, null 契约已生效）**：① `getEnvIssue()` 只校验 env/ROS_DISTRO/ROS_VERSION 三变量, 不校验 ros2 CLI 与 AMENT_PREFIX_PATH——env 变量合法但 `ros2 pkg list` 实际失败完全可能; ② 自 2026-09-01 起 `Ros2ServiceApi` 查询类改为 **null 契约**(`null`=失败, `[]`/""=成功但空):`pkg_list` 失败 → `null`; ③ `loadSystemPackageList` 的 `names === null` 守卫生效 → 失败不标记 loaded、`systemAvailable` 不再误报。⇒ 空/失败由 null 与 [] 明确区分, 但**候选为空(无环境/冷启动)仍是常态, 降级链必须完整**。

> 注：原讨论稿 §3 引用的 `src/ros/ros.ts`（getPackageNames）与 `src/build-tool/create/*` 路径均已过时（08-28/08-30 重构），现状分别收敛到 `src/ros2` service API 与 `package-service/create/*`。

## 4. 模块结构

```
build-tool/package-service/create/
  dep-pick.ts(新增, 交互层)   — pickDeps(kind): Promise<PickDepsResult | null>(null=取消)
     取候选(工作区 unignored ∪ 环境 system) → QuickPick 多选 → 按需自定义输入 → 合并 → 显式校验(重开循环); 零校验逻辑
  dep-merge.ts(新增, 纯函数)  — mergeDeps / validateFinal(可单测, 零 vscode; 抽独立文件避免 UI 壳连带 vscode)
  dep-lang.ts(2026-09-06 新增, 纯函数) — 来源/语言判定(工作区? 纯 Python?) + unionCandidateNames(候选并集)
  dep-parse.ts(现有 + depAnnotation) — parseDepList / validateDepList / DEP_BUILTIN / depAnnotation(元信息标注)
  create-package-command.ts   — inputDeps(kind) 变薄: 调 pickDeps; 其余不动
package-core(已有, 只读不改) — getState().unignored(工作区候选, 含未构建) + getState().system(环境候选, 只表示工作空间以外)
```

**纯函数（可单测，不依赖 vscode）**：

| 函数 | 职责 |
|:--|:--|
| `mergeDeps(selected: string[], custom: string[], kind): string[]` | 合并 + 去重（勾选∩自定义、DEP_BUILTIN 静默过滤） |
| `validateFinal(deps: string[], kind): string | null` | 显式逐项校验（复用 validateDepList），返回首个错误 |

UI 壳（`pickDeps`）只做：候选获取、QuickPick、按需 showInputBox、错误提示重开——不掺校验逻辑。

**可选**：弹窗走 `src/ros2/host/window.ts` 中转壳（showQuickPick/showInputBox 绑定壳），与 ros2/registry 一致；create 子域目前直用 vscode.window，是否切换实施时定（涉及跨子域依赖方向）。

## 5. 校验与去重规则（定稿）

| 场景 | 处理 |
|:--|:--|
| 勾选系统包 | 天然合法，不格式校验 |
| 自定义输入 | 内联 `validateDepList`（格式/升级/跨体系，边输边报、锁回车） |
| 勾选与自定义重复 | 静默去重（保留一个） |
| 与 DEP_BUILTIN 内置重复 | 静默过滤（现有生成器行为） |
| 勾选命中升级信号（如 cpp-only 勾 rclpy） | description 预标注「⚠️ 需双语言/混合包」；勾选不拦截；最终显式校验兜底 → 弹错重开 |
| 勾选命中跨体系不可能（如 ament_python 勾 rclcpp） | 同上（「⚠️ 当前类型无法使用」） |
| Esc（任意阶段） | 终止流程 |

**元信息标注规则**（QuickPick description，按 kind 动态计算；纯文本，不用 emoji）：

- **内置依赖自动隐藏**：命中 DEP_BUILTIN[kind] 的候选不出现在列表（excludeBuiltin）——勾了也会被 mergeDeps 静默过滤，留在列表纯属误导；
- `[需双语言/混合包]`：命中 UPGRADE_DEPS[kind]（升级信号）
- `[当前类型无法使用]`：命中 IMPOSSIBLE_DEPS[kind]（跨体系不可能）

## 6. 交互细节

- `showQuickPick(items, { canPickMany: true, matchOnDescription: true })`——按包名或元信息过滤均可用；
- 自定义项 `alwaysShow: true` 且固定首位（防过滤后消失）；
- 数百项性能：QuickPick 原生过滤足够，无虚拟化需求；候选获取惰性，不做后台预取；
- 多选确认 Enter；取消 Esc（终止）；自定义输入框取消（Esc）同样终止（2026-09-01 起依赖 Esc=终止的统一语义）。

## 7. 降级策略

| 条件 | 行为 |
|:--|:--|
| 工作区侧 `unignored` 非 null | 进候选（**含未构建包**），并作为来源/语言标注权威表 |
| 工作区侧 `unignored` null(未刷新/未知) | 工作区侧缺席，环境侧照常 → **不整体降级** |
| 环境侧 system 域 null(未刷新/未知) | 现跑 `pkg_list`；再失败 → 环境侧缺席（工作区侧照常） |
| 环境侧 system 域 `[]`(已刷新但真没有外部包) | 环境侧为空，不现跑 |
| 两侧都拿不到候选 | 纯输入框（现状），零回归 |
| 无 ROS 环境 | 工作区侧通常仍有 `unignored` → 仍可多选；两侧皆空才同上一行 |

降级判据自 2026-09-14 起为"**两侧皆空**"（此前为"system 为空"）：并集后任一侧有数据即正常多选，只有 `unignored` 未刷新 **且** 环境侧现跑失败时才走旧逻辑。

## 8. 实施计划（分步，每步可验收）

1. **候选读取**：`packageCore.getState().system` 取 name 列表（null → 现跑 pkg_list; [] → 降级; 非空 → 直接用）+ 纯函数单测；
2. **dep-pick.ts 纯函数**：`mergeDeps` / `validateFinal` + 单测（含升级/跨体系命中、内置过滤、重复去重）；
3. **dep-pick.ts UI 壳**：`pickDeps(kind)`（候选获取 → 多选 → 自定义 → 合并 → 显式校验重开）；
4. **create-package-command.ts**：`inputDeps` 改调 `pickDeps` + 降级分支（null → 纯输入框；Esc → 终止）；
5. **集成手工验证**（见 §9 清单）；
6. **文档同步**（本文件修改记录 + create/README.md §7 如有涉及）。
