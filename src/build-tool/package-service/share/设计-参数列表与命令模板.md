# 命令参数模板机制(设计稿 · 待裁定)

> 本稿把你的设想写成可确认的规格。**未裁定项集中在 §8**,确认后再落代码(`share/types.ts` / `expand.ts` / `pick-preset.ts` / `defaults/`)。

## 0. 一句话

把「命令怎么拼」从代码搬到设置:**一条命令模板 + 一份预设参数表**,由扩展按用户的两级选择展开。
机制**与命令无关** —— 先给 `colcon build` 用,之后 `ros2 run` / `ros2 launch` / `ros2 test` / 自定义命令复用同一份引擎与同一个人机交互。

## 1. 三层结构

| 层 | 内容 | 谁提供 |
|---|---|---|
| **命令模板** | 一条命令字符串 + 占位符,如 `colcon build --packages-select ${package_list} ${1}` | 设置(每个命令一份) |
| **命名动态参数** | 调用方在展开时传入的实参:`${package_list}`(构建)、`${pkg}` / `${executable}`(run)、`${launch_file}`(launch)… | 调用方(第一级弹窗或其它选择器) |
| **预设参数表** | `argv_list: [{argv, describe}]` + `custom`(自定义输入的描述) | 设置(每个命令一份) |

## 2. 占位符语义

| 占位符 | 含义 | 展开时机 |
|:--|:--|:--|
| `${<name>}` | 调用方传入的**命名动态参数**(`package_list` / `executable` / `launch_file` / …) | 第 3 步 |
| `${0}` | **自定义输入**:二级弹窗第 1 项(**仅当模板里用到 `${0}` 时才出现**);选中后追加一个输入框,用户手写 argv 片段 | **第 1 步(最先)** |
| `${1}` … `${n}` | 第 n 条预设的 `argv`(下标从 1 起) | 第 2 步 |
| 其它 `${x}` | 未知占位符 → **原样保留 + 记日志**(不静默吞掉) | — |

**`${0}` 的嵌套规则(你的要求)**:`${0}` **优先在 `${1}..${n}` 内部展开**,所以预设可以引用自定义输入,例如
`{ "argv": "--install-base ${0}", "describe": "自定义安装目录" }`。

### 2.1 模板是**自由文本**:顺序、位置、重复、省略全由用户决定

**表示形式(2026-10-07 起,由词数组改回;09-28 曾数组化)**:设置侧 `template` 是**一段命令文本**(含命令名),展开前按 shell 词法(空格与引号)切分——文本里可写引号包含空格的词;**出厂默认随设置预存**(`default`),用户不改也直接可见可改。非字符串写法(含 09-28~10-07 短暂存在的词数组)在 mergeSpec 视为未给,回落出厂默认(未分发无存量,兼容层已于同日拆除)。本节全部自由度不变:顺序/重复/省略/换命令照旧。

引擎对"命令长什么样"**没有任何假设** —— 它只做占位符替换,不认命令名、不认 verb、不管参数顺序:

| 自由度 | 例子 | 用例 |
|:--|:--|:--|
| **顺序**任意 | `${3}` 排在 `${1}` 前面 | `槽位顺序自由` |
| **位置**任意 | `${1}` 放在 `build` **之前**(实测 `--log-level` 这类全局参数**必须**在 verb 之前,放后面 colcon 直接退码 2) | `槽位位置自由` |
| **重复**出现 | 同一个 `${1}` 写两次 → 两处都填 | `同槽位重复出现` |
| **完全不出现** | 模板退化成一条纯字面量命令 | `占位符可以完全不出现` |
| **换成别的命令** | `ros2 run ${pkg} ${executable} ${1}` —— 这正是"共享给 run/launch"的基础 | `甚至可以换掉整条命令` |

**`${packages}` 与 `${packages_select}` 两种口径都给**(便于自由重排):

- `${packages_select}` = **成对片段** `--packages-select a b`,无包时**整段消失**(默认模板用它,避免留下裸 flag);
- `${packages}` = **裸包名** `a b`,想自己写别的参数时用,如 `colcon build --packages-up-to ${packages}`。

### 2.2 命名动态参数清单(**收缩后 5 个**;值为逐条对齐实现)

**先分清两类**(这决定了模板里该怎么写):

- **裸值** = 变量只给"值",flag 字面量写在模板里(如模板写 `--base-paths ${base_path}`);
- **片段** = 变量自带 flag,不用时整段消失(如模板写 `${clean}` 而不是 `--cmake-clean-cache ${clean}`)。

| 变量 | 类别 | 展开后长什么样 | 空 / 缺省时 | 值从哪来 | 今天的对应 |
|:--|:--|:--|:--|:--|:--|
| `${base_path}` | 裸值(**已自动加引号**) | `/home/ros2/roa2_ws`;含空格 → `"/tmp/a b"`(整体仍是**一个** argv) | 必给 | 工作区根 | `--base-paths <ws>` |
| `${packages_select}` | **片段**(自带 flag) | `--packages-select p10 p11` | 无选中包 → **空串(整段消失)** | 第一级多选结果 | `args.push("--packages-select", ...pkgs)` |
| `${clean}` | **片段** | `--cmake-clean-cache` | `false` → 空串 | 形态检查结论 `cleanCache` | `if (opts.clean)` |
| `${install_method}` | **片段** | `--symlink-install` | 实体 → **空串** | **设置** `ROS2.build.installMethod`(经 `resolveInstallType()`;auto=平台默认) | `toInstallTypeFlags()` 的形态那一半 |
| `${install_layout}` | **片段** | `--merge-install` | 分包 → **空串** | **设置** `ROS2.build.installLayout`(同上) | `toInstallTypeFlags()` 的布局那一半 |

**被收缩/替换掉的(2026-09-22 用户裁定;除注明外,现在写进模板都会原样保留 + 记日志)**:

| 去掉的 | 原因 | 替代做法 |
|:--|:--|:--|
| 4 条**安装交叉预设**(符号+合并 / 符号+分包 / 实体+合并 / 实体+分包) | 两轴改由**两个独立变量**表达 ⇒ 交叉预设整体删除(不是"降为种子",而是**不存在**) | 见上表 `${install_method}` / `${install_layout}`(**由设置接管**) |
| `${log_level}` | 详细输出改由**预设**承载(见 §2.3 B 类:`${1}` = `--log-level debug`) | 勾预设 1(它落在 verb **之前**;实测 `--log-level` 放 verb 后 colcon **退码 2**) |
| `${parallel}` | 写死并行度(如 4)不随设备变,没有意义 | colcon 默认参数文件(`~/.colcon/defaults.yaml` / `$COLCON_DEFAULTS_FILE`;本机已装 `colcon_defaults`)或终端手敲 |
| `${event_handlers}` | 值写死;详细输出的 handlers 部分改由**预设**承载 | 勾预设 2(只给 handler 名 `log_command+`,与模板字面量 `--event-handlers console_cohesion+` 合成完整的那一条 —— 与今天逐字节相同,且不会出现重复 flag) |
| `${build_type}` | 写死 `RelWithDebInfo`(不暴露变量) | 改模板字面量(默认模板已无 `${0}`,要用自定义输入需先把 `${0}` 加回模板) |
| `${packages}` | 与 `${packages_select}` 重复(裸包名无人用) | 只留成对片段 `${packages_select}` |
| `${0}`(默认模板中) | **不使用** | **功能保留**:把 `${0}` 加回模板,二级弹窗的「自定义输入」项与输入框即恢复 |

**两条硬规则**:

1. 变量名是**调用方(代码)给死的**,不是用户自定义的;用户在模板里**引用**它们。
   在模板里造一个不存在的名字(如 `${basepath}` 拼错、或上面被收缩掉的 `${parallel}`)会命中**未知占位符** ⇒
   **原样保留 + 记日志**(`unknown` 列表),**不会静默变空** —— 拼错会以"命令行里出现一个字面量"的形式当场暴露;
2. 引擎**不校验**变量有没有值、也不校验组合是否合法:空片段 = 这段消失(所以 `${packages_select}` / `${clean}` 未用时
   不会留下裸 flag);矛盾组合由 colcon 自己报错。

**这些名字是"构建专属"的**:共享给 `ros2 run` / `ros2 launch` 时,调用方给的是另一组(`${pkg}` / `${executable}` / `${launch_file}` …)
—— 引擎不预设任何名字,只认"调用方传进来的 dynamics"。

**占位符全表(收缩后)**:`${1}`..`${n}` 第 n 条预设的 argv(槽名**就是序号本身**,不带前缀)/
`${base_path}` `${packages_select}` `${clean}` `${install_method}` `${install_layout}`;
`${0}` 自定义输入(**功能保留,默认模板未使用**);其余一律"未知占位符"。

### 2.3 我们**自动填入**的全部内容(清单,防漏)

| 类别 | 内容 | 谁决定 / 何时填 |
|:--|:--|:--|
| **A. 命名动态参数(5 个)** | `base_path` / `packages_select` / `clean` / **`install_method`** / **`install_layout`** | 前三个按运行期事实填;**两轴来自设置** |
| **B. 出厂预设(2 条 argv)** | 详细输出的两半:`${1}` = `--log-level debug`(须在 verb 前)、`${2}` = `log_command+`(与字面量 `--event-handlers console_cohesion+` 合成) | **只是设置项的默认值**,**勾选才填**,用户可改描述/调顺序/**全删** |
| **C. 模板里的固定字面量(不是变量)** | `colcon` / `build` / `--event-handlers console_cohesion+` / `--base-paths` / `--cmake-args` / `-DCMAKE_BUILD_TYPE=RelWithDebInfo`(写死)/ `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` | 出厂默认模板的**文本**,用户可整条重写 |

**对照用户口径("配置清理 / 日志等级 / 发布等级 / 布局模式 / 安装类型")**:

- ① 配置清理 = **A 类** `clean`;
- ② 日志等级 = **B 类预设 1**(`--log-level debug`);
- ③ 发布等级(CMAKE_BUILD_TYPE)= **已收缩**:写死在模板字面量里(不再是变量);
- ④ 布局模式 + ⑤ 安装类型 = **A 类的两个变量** `${install_layout}` / `${install_method}`,**值由设置接管**
  (`symlinkInstall` / `installLayout` 经 `resolveInstallType()` 还原成两轴);**不再有交叉预设**。

⇒ 完整口径:**5 个命名动态参数 + 2 条预设(详细输出两半)+ 模板里那些固定字面量**;没有其它隐藏的自动填入。

### 2.4 槽内多条备选("组")——OR 逻辑:**展示全部,一组最多生效一条**

`argv_list` 的每个元素 = **一个槽**(对应模板里的 `${槽号}`);元素两种写法:单条 `{argv, describe}`,或**一组** `[ {…}, {…} ]`。

```jsonc
"argv_list": [
  { "argv": "--continue-on-error", "describe": "失败继续" },                       // 槽 1:单条
  [ { "argv": "--cmake-args -DCMAKE_BUILD_TYPE=Debug",       "describe": "Debug 构建" },   // 槽 2:一组三条
    { "argv": "--cmake-args -DCMAKE_BUILD_TYPE=Release",     "describe": "Release 构建" },
    { "argv": "--cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo", "describe": "默认构建" } ]
]
```

| 规则 | 语义 | 锁定用例 |
|:--|:--|:--|
| **展示全部** | 二级弹窗把同组备选**并排全列出**,每项 `detail` 标注"→ 填入 `${k}`",让用户看清"这几条在争同一个槽" | `弹窗**展示全部**备选…` |
| 单选即用 | 同组内勾任意一条 ⇒ 该槽 = 它的 argv | `同组只勾第二条…` |
| **同组多选 ⇒ 取书写顺序第一条** | **一组最多生效一条**(用户裁定 2026-09-22);其余勾选只显示、不进命令行 | `同组三选 ⇒ 只应用第一条`、`勾第二+第三 ⇒ 仍取第二条` |
| **不顺延** | "第一条被勾中"的 argv 若为空串 ⇒ 该槽就是空,**不**退到第二条(保持"勾了谁就是谁") | `"第一条被勾中的备选"展开为空…` |
| 空组 | `[]` **占位但不产出条目**(后面槽号不错位);全是空组 ⇒ 视同"没有预设"(弹窗该跳就跳) | `空组占位但不产出条目`、`全是空组` |
| 记忆 | 勾选与记忆都用**平坦下标**(展平顺序 = 槽号升序、槽内按书写先后;`picked: number[]` 语义不变)。"每槽一条"时 `index === slot-1` ⇒ **老记忆天然兼容** | `flattenArgList…老记忆兼容` |

**位置提醒(别踩)**:组只能表达"**同一个位置**的互斥备选"。默认 spec 里"详细输出"的两半**故意是两个槽**
——`${1}` 在 `build` **之前**、`${2}` 在 `--event-handlers` **之后**;它们位置不同,**不能合并成一组**
(否则 `--log-level debug` 会落到 verb 之后,实测 colcon **退码 2**)。

## 4. 展开算法(纯函数,五步)

1. **归一化**:`template` / `custom` / `argv_list` 缺省合并该命令的**出厂默认**(见 §7 边界);
2. **`${0}` 预展开**:在**每条预设 `argv`** 内替换 `${0}`;
3. **填槽**:`${i}` ← 第 i 条预设的 `argv`(未选中 / 越界 → 空串);
4. **填命名动态参数**:`${package_list}` ← 选中包名(空格分隔)等;
5. **切分**:按 shell 词法切成 `string[]`,折叠多余空白;**结果为空 → 报错不执行**(不允许空命令)。

## 5. 二级弹窗(通用组件,与命令无关)

**预设与用户平级**:出厂预设只是设置里那份 spec 的**默认值**,用户可以一条不剩地删干净;模板也可以不用 `${0}`。
于是二级弹窗按 `presetPickPlan()` 自动选择**三种形态**:

| 模板含 `${0}` | 预设条数 | 形态 | 行为 |
|:--|:--|:--|:--|
| 否 | 0 | `none` | **完全不弹**(没有任何占位符要填)⇒ 直接构建 |
| 是 | 0 | `input-only` | **直接弹手动输入框**(跳过列表);**Esc = 取消本次流程**,空输入回车 = 不加参数继续 |
| 其余 | — | `list` | 弹多选列表:第 1 项 = 自定义输入(选中后追加输入框),其余 = 预设项 |

列表形态的细则:

- 只有模板里用到 `${0}` 时才加"自定义输入"那一项(用户裁定 Q7:否则不弹);
- 预设项的 label 取 `describe`、description 取真实 `argv`;
- **多选**,且**不做任何互斥/合法性校验**(用户裁定 Q5):矛盾组合由 colcon 自己报错;
- **Esc 一律 = 取消本次流程**(用户裁定:列表 Esc、自定义输入框 Esc 都是取消,不存在"保留勾选继续"这种中间态);
  只有"输入框里**空串回车**"才是"不追加自定义、其余勾选照用";
- 复用者只提供:标题 / 占位符 + 自己的 spec + 自己的命名动态参数。

## 6. 可共享性检查(为什么这套能共享给 run/launch)

| 命令 | 命名动态参数 | 模板样例 |
|:--|:--|:--|
| `colcon build` | `${package_list}` | `colcon build --packages-select ${package_list} ${1} ${2}` |
| `ros2 run` | `${pkg}` `${executable}` | `ros2 run ${pkg} ${executable} ${1} ${0}` |
| `ros2 launch` | `${launch_file}` | `ros2 launch ${launch_file} ${1}` |
| `ros2 test` / 自定义 | 任意 | 任意 |

⇒ 机制与 colcon 无关;`share/` 内不出现具体命令名(示例与 `defaults/` 除外)。

## 7. 边界(必须守住)

- **不绑定命令**:引擎不含 colcon/run/launch 分支;命令专属默认值放 `defaults/`;
- **纯函数 + 通用弹窗**:不读写文件、不落盘状态(记忆上次选择仍归各命令自己的状态文件);
- **不猜**:不校验参数合法性、不修正用户写法;
- **不转义**:按 shell 词法切分(引号语义保留);等价于用户自己敲终端,扩展不加壳;
- 未知占位符**原样保留 + 日志**;展开为空 → 明确报错。

| **Q5** | 多选会不会选出**矛盾参数** | **不做约束**:机制只保证"**替换正确、预设正确**";矛盾组合交给 colcon 报错 —— 既然提供扩展性,就不强制约束用户(用户裁定原文:"我们只需要做好自己的替换工作就好,并且保证预设正确") |
| **Q6** | 默认预设用什么 | 之前那三条(`--install-base` / `--continue-on-error` / `--cmake-force-configure`)是**随手举例,不得当成实际使用** ⇒ 换成**真实的双轴 4 组合**(⚠️ 该方案已被 **Q13** 取代:两轴改回变量) |
| **Q7** | 「自定义输入」项何时出现 | **模板里用到 `${0}` 才出现**;模板没有 `${0}` ⇒ 二级弹窗里**根本没有该项**(不弹) |
| **Q8** | 预设的地位 | **预设与用户平级**:出厂预设只是设置里那份 spec 的默认值,用户可**全部删干净**。由此二级弹窗自动三态(见 §5):模板无 `${0}` + 无预设 ⇒ **整个第二级都不弹**;无预设但有 `${0}` ⇒ **直接跳手动输入**(不弹列表)。引擎里**不认识任何具体预设**(没有 colcon/双轴的名字),删干净后一切照常 |
| **Q9** | 模板的**顺序**能不能改 | **能,而且什么都能改** —— 模板是自由文本:顺序 / 位置(可放在 verb 之前)/ 重复 / 省略全由用户决定,甚至可换成别的命令(见 §2.1)。原先把默认模板写成"数组拼接"会让人误以为结构固定 ⇒ 已改为**一段字符串**并注明;同时把设置项**登记进 `package.json`**,否则用户根本看不到、改不了 |
| **Q10** | 变量太多,收缩 | **只留 4 个**:`${base_path}` `${packages_select}` `${clean}` `${log_level}`。去掉 `${parallel}`(写死并行度无意义)、`${event_handlers}`(写死 `console_cohesion+`,放弃"每个命令都打印")、`${build_type}`(写死 `RelWithDebInfo`)、`${packages}`(与 `packages_select` 重复)(见 §2.2)(⚠️ 其中 `${log_level}` 已被 Q14 删除;`${event_handlers}` 的能力已由 Q14 的预设 `${2}` 找回) |
| **Q11** | 槽名写法 | **就是序号本身 `${1}`..`${n}`**,不带前缀(用户明确"这个 n 是不要的");`${n1}` 之类**不是**槽名 ⇒ 命中未知占位符 |
| **Q12** | 那 4 条预设的地位 | **降为"种子"** —— 只作设置项 `argv_list` 的默认值:**无元数据、无下标特权**(要判断安装形式一律从 argv 解析)(⚠️ 该 4 条预设已被 **Q13** 整体删除) |
| **Q13** | 两轴怎么表达 | **回归为两个独立变量 + 设置接管**(用户裁定:删掉 4 条交叉预设,两轴"由设置接管"):`${install_method}` ← `ROS2.build.symlinkInstall`、`${install_layout}` ← `ROS2.build.installLayout`(均经 `resolveInstallType()`)。**收益**:Windows 恒实体的平台保护照旧、前瞻检查入参无需改、预设表回归纯粹 |
| **Q14** | `${log_level}` 与 `${0}` 的处置 | **删除 `${log_level}`**:详细输出改由**两条预设**承载 —— `${1}` = `--log-level debug`(落在 verb 之前)、`${2}` = `log_command+`(与字面量 `--event-handlers console_cohesion+` 合成);**默认模板删除 `${0}`**(不使用,但**功能保留**:加回模板即恢复「自定义输入」项与输入框) |
| **Q15** | Esc 的语义 | **Esc 一律 = 取消本次流程**(列表 Esc、自定义输入框 Esc 都一样;用户裁定"也是取消,Esc 都是取消")⇒ 不存在"保留已勾选、只放弃自定义"的中间态;唯一例外是**输入框空串回车** = 不追加自定义、其余勾选照用 |
| **Q16** | 能不能"一组备选共用一个槽"(OR) | **能**(见 §2.4):`argv_list` 元素可以是**一组**;弹窗**全部列出**,勾任意一条即填该槽;**同组多选时只应用"书写顺序里的第一条"**(用户裁定:保证一组最多生效一条);空组占位不错位;记忆用平坦下标 ⇒ 老记忆兼容 |

**出厂预设(只剩详细输出的两半;仅默认值,顺序/描述/条目随用户)**:

| 槽位 | argv | 描述 |
|:--|:--|:--|
| `${1}` | `--log-level debug` | 详细输出 1/2:打开 debug 日志(**必须在 build 之前**) |
| `${2}` | `log_command+` | 详细输出 2/2:记录每个被调用的命令(与字面量合成完整 flag) |

## 10. 接线(已执行)+ 实测约束

**实测约束(VM,colcon build 实跑)**:

| 试验 | 结果 | 对设计的含义 |
|:--|:--|:--|
| `colcon build … --log-level debug` | **退码 2**(argparse 拒绝,直接打 usage) | **全局参数必须在 verb 之前** ⇒ 预设 `${1}` 只能放在模板的 verb 之前 |
| `colcon --log-level debug build …` | 退码 0(DEBUG 行出现) | 默认模板已如此 |
| `--event-handlers` 出现两次 | **退码 0**,后一次生效 | 重复 `nargs='*'` 参数安全 ⇒ **备选用法**:预设写整段 `--event-handlers …` 可**覆盖**前面的值。当前默认预设 `${2}` 只给 `log_command+`,与字面量合成一条,**不产生重复** |

**接线落点(已执行)**:

| 落点 | 内容 |
|:--|:--|
| `build/share-spec.ts`(新) | 读设置 + 合并默认 + 装填动态参数 + 展开(适配层放这里:引擎不认识 vscode、ros2 不认识模板) |
| `build/smart-build.ts` | 二级弹窗 → `pickPresets()`(三态/多选/Esc 一律取消);命令 → `expandColconBuild()`;记忆 → `pickedPresets`/`customArgs` |
| `build/register-commands.ts` | 右键单包 Release = 模板原样;**Debug = 展开后追加 `--cmake-args -DCMAKE_BUILD_TYPE=Debug`**(模板写死 RelWithDebInfo 且不再暴露 `${build_type}`) |
| `ros2/api` + `ros_task_runner` | `ColconBuildOptions` = `{ base_path, argv(必填), packages? }`;`colcon_build` 只执行(`command=argv[0]`/`args=argv.slice(1)`),空 argv ⇒ 报错不执行。**内置构造 `toColconBuildCommand` 已删除,不留回退路径**(开发期不留历史包袱) |
| 右键单包(Release/Debug) | 调 `expandColconBuildWithMemory()`:**不弹任何参数选择**,直接套用选择记忆;记忆为空 ⇒ 等价于直接用模板;Debug 再追加一组 `--cmake-args -DCMAKE_BUILD_TYPE=Debug` 覆盖 |
| `build-memory` / `state-file` | `buildConfig` 下线 → `pickedPresets` + `customArgs`(旧字段不再读) |

**接线要点**:

1. 两轴的权威来源仍是**设置**(`resolveInstallType()`),接线时把它的值喂给 `colconBuildDynamics({ install_type })` 即可 ⇒
   **不需要**改前瞻检查的入参(它们本来就用 `resolveInstallType()`);
   `axesFromArgv()` 保留为"从最终命令行反解"的校验工具(用户若自定义模板改了 flag,可用它核对);
2. **Windows 保护照旧生效**(因为两轴仍来自 `resolveInstallType()`,它在 Windows 恒 `copy`)—— 这是把两轴从"预设勾选"改回"设置接管"后的**额外收益**;
3. 记忆(上次勾了哪几条)建议存 **argv 而不是下标** —— 用户重排后下标会错位(argv 是唯一事实,与 Q12 一致)。

**接线两步**:

1. `ros2/commands/ros_task_runner.ts:colcon_build` —— 命令构造改为
   `expandCommand(spec, { dynamics: colconBuildDynamics(...), picked, custom })`(行为由等价性单测兜底);
2. `build/smart-build.ts` —— 二级弹窗换成 `pickPresets(spec, …)`,选择结果写进记忆。
