# package-core:数据源与事件/重建链路现状详解(2026-09-06)

> 定位:本报告是 package-core 当前(2026-09-06)结构的**细粒度对照文档**——文件/函数/字段级,
> 供"站在整体观察"时不依赖逐文件翻代码。正文描述的是**当前实现**(含 2026-09-06 20:18 的
> doRebuild 前置 colcon 修复),不是设计稿;历史设计见 `src/build-tool/package-core/DESIGN.md`。

## 1. 一句话定位

package-core = 工作区包的**权威数据中心 + 变化广播器**:
对外只承诺"当前工作区有哪些包、哪些被忽略、各是什么 buildType"的一致视图(5 域),并在视图变化时通知消费方。
**不对外暴露内部用了 walk 还是 colcon**(实现细节)。

## 3. 装配顺序(`createPackageCore`)

1. `workspaceRoot`(缺省 `workspaceFolders[0].uri.fsPath`);
2. `createPackageFetcher({workspaceRoot, refreshIntervalMs, watchDebounceMs:500})` → `createTimer(60s)` + `createFsWatcher()`(根 undefined = 不监听,无头用);
3. `createColconListExecutor({ exec: cmd => composeApi.commandRunner.exec(cmd) })`(colcon 子进程执行口);
4. `createWorkspaceData()`:`getSharedPackageCache(workspaceRoot)`(**单例**);
5. 注入:`cache.setColconListExecutor(() => colconList(workspaceRoot, excludedFolders))`、`cache.updateConfig({excludedFolders, followSymlinks, walkTimeouts})`;
6. `new DataLayer(fetcher, cache, systemPackagesProvider)`——构造内立即 `void forceRefresh()`(首载);
7. `new PackageFacade(data)` 薄门面,组装 `core`。

## 4. 事件源头(两路,汇成一个 DriverEvent 流)

**A. fs 监听**(`fs-watcher.ts`):
- `RelativePattern(root, "**/package.xml")` + `RelativePattern(root, "**/COLCON_IGNORE")` 两个 watcher;
- `onDidCreate/onDidChange/onDidDelete` 六路回调 → `schedule({kind: workspace-package-changed | ignore-marker-changed})`;
- 500ms 去抖,flush 时**按 kind 合并、各发一次,且不带路径(dir 字段不填)**;
- 只管这两类文件的信号,不做探查。

**B. 60s 定时**(`timer.ts`):`setInterval(60s)` → `{kind:"timer-tick"}`;`intervalMs<=0` 禁用。

`event/index.ts` 把两路并成 `PackageFetcher.onExternalChange`。

## 5. DataLayer 事件分发(`data/index.ts`)

构造订阅:
- `fetcher.onExternalChange → handleDriverEvent`;
- `cache.onContentChange → refreshFromCacheSnapshot`(缓存内容真变时直接用最新快照重组装,不 invalidate)。

`handleDriverEvent` switch:

| 事件 | 动作 |
|---|---|
| `workspace-package-changed` / `ignore-marker-changed` | `refreshWorkspace("refresh")`:懒重建 = `cache.invalidate()`(置 dirty)→ `cache.ensureFresh()` |
| `timer-tick` | `refreshWorkspace("rebuild")`:强制 `cache.rebuild()`(无条件) |

两者拿到快照后都走 `commitFromSnapshot(snap, this.state.system)`。

## 6. PackageCache 内部(`data/package-cache.ts`)

**字段**:`snapshot`(双缓冲)/ `rebuildPromise`(单飞)/ `dirty` / `walkReady` / `colconListExecutor`。

**`PackageSnapshot` 组成**:
```
unignore: WorkspacePackage[]   // colcon list 权威名单
ignore:   WorkspacePackage[]   // walk 派生(同目录 COLCON_IGNORE)
entries:  PackageScanEntry[]   // walk 全量画像(name/buildType/isValid/hasColconIgnore/parentIsSrc)
timedOut / elapsedMs / generatedAt
contentFingerprint             // 覆盖 entries+unignore+ignore+colconReady,排序拼接
colconReady: boolean           // colcon 是否成功注入过("成功但空"≠"没跑")
```

**方法语义**:
- `syncUnignore()`:无执行器 → warn 返回 [];`await colconListExecutor()` 失败 → warn 保持旧值(不标记 ready);成功后 `attachBuildType(unignore, snapshot.entries)` 按 path 补类型 → 替换快照(unignore+colconReady:true)→ 指纹变才 fire `onContentChange`。
- `invalidate()`:`dirty=true`。
- `ensureFresh()`:`snapshot && walkReady && !dirty` → 直接返回;否则 `rebuild()`。
- `rebuild()`:单飞 → `doRebuild()`。
- **`doRebuild()`(当前实现,2026-09-06 20:18 修复后)**:
  1. `if (colconListExecutor) await syncUnignore()`(**每次重建先重跑 colcon** —— 本轮修复点);
  2. walk:`scanWorkspacePackages(...)` → `entries`;
  3. 差异诊断:`colcon 名单 vs walk 合法名单` 有差 → info 日志带包名;
  4. `ignore = entries.filter(isValid && hasColconIgnore)`;
  5. `unignore = attachBuildType(prevUnignore, entries)`(只补类型;**不新增、不删减**);
  6. 封装 snapshot(保留 colconReady)→ 指纹 → 原子替换 → `dirty=false, walkReady=true` → fire `onDidChange`(替换即发)→ 指纹变才 fire `onContentChange`;
  7. 失败:保留旧快照、置 dirty、返回旧值(空则返回 colconReady=false 空快照)。

## 7. 两条取数路与"探查"规则

**walk**(`scan/package-scan.ts`):`walkWithTimeout(root, "package.xml")`(内置排除目录名 + 用户 `search.excludeFolders` 路径过滤 + 双超时 + maxDepth + 不跟随符号链接)→ 每个命中的 `dir` 走 `buildEntry`:
- `analyzePackageDir(dir)`;
- 同目录 `COLCON_IGNORE` 探测;
- `parentIsSrc = basename(dirname(dir)) === "src"`。

**探查唯一尺子**(`scan/package-xml.ts` `analyzePackageDir`):读 package.xml → lezer 严格解析(根必须 `<package>`,取 `<name>`,`<export><build_type>`);
合法 = well-formed + 根 package + 非空 name + **build_type 同类型校验**:
- `ament_python` → 目录须有 `setup.py` 或 `pyproject.toml`;
- `ament_cmake` / `cmake` → 须有 `CMakeLists.txt`;
- 未声明或其它值 → 不合法。
colcon 与 walk 对同一份 package.xml 用**同一函数**,无两套合法性。

**colcon list**(`scan/colcon-list.ts`):命令 `colcon --log-base <nul|/dev/null> list --base-paths "<workspaceRoot>"`;
每行 `split(/\s+/)` → `[name, rawPath]`,`pkgPath = path.resolve(ws, rawPath)`(兼容相对/绝对)→ `isPathExcluded` 过滤 → **再 `analyzePackageDir` 一次**(取 name/buildType/合法)→ 收录 `{name, path, buildType}`。
colcon 额外拥有 walk 没有的**祖先 COLCON_IGNORE 语义**(父目录标记 → 整棵子树不算),故 unignore 以 colcon 为权威、walk 只兜底。

## 8. 快照 → 域 → 事件

`commitFromSnapshot`(debug 日志出处):`colconUnignored = unignore.map(toEntry)`;`fallback = fallbackUnignoredFromWalk(entries)`(walk 合法 && !hasColconIgnore);`buildable = colconReady ? colconUnignored : fallback`;类型未齐防御(存在 undefined buildType 且 colconReady → 保持旧域);`commit({unignored: buildable, ignored, system})`。

`commit`:组装 5 域
```
workspace = deriveWorkspace(unignored, ignored)  // mergeByName 按 name 去重,unignored 优先
all       = deriveAll(workspace, system)          // 任一上游 null → null
```
`domainSig(域)` = `name@dir@buildType` 排序拼接,`null → "!null"`;逐域比对,**哪个域变了才在事件里带哪个域**;全没变不发。

**5 域 null 契约**(state.ts):`null`=未刷新/未知;`[]`=已刷新但真空;派生域上游 null → null(不冒充空)。

## 9. 命令口精确行为

| 命令口 | 行为 |
|---|---|
| `ingestPackageCreated(xmlPath)` | `dir=dirname` → analyze 不合法直接 return;`ignored=同目录 COLCON_IGNORE`;unignored/ignored 任一 null → 仅 `invalidate()` 早退;否则 `dedupeAdd` 入 unignored(或 ignored)→ `invalidate()+commit()` |
| `toggleIgnore(dir)` | 写/删 COLCON_IGNORE → 重 analyze → 包在 unignore ↔ ignored 间迁移 → `invalidate()+commit()` |
| `getBuildPackages()` | 快照 `colconReady` → 直接返回 `state.unignored`;否则 `syncUnignore()`(此处才跑 colcon)→ 类型全齐才 commit → 返回 |
| `refreshSystem()` | 注入 `pkg_list` 提供者 → `{name, dir:"", buildType:""}`;失败/未注入 → 保持旧值;只动 system/all 域 |
| `forceRefresh()` | = `refreshWorkspace("refresh")` |

unignore 一旦 colconReady 便永久停留在"上次 colcon list"的旧名单。这精确解释远端问题:
create 后 `colcon=10/fallback=11`,且 60s 周期修不好(它只 walk)。
**修复(2026-09-06 20:18,已落地)**:doRebuild 每次重建先 `syncUnignore()` 刷新 colcon 权威;

### 12.1 语义定稿:水池 × 水桶 双正交模型(用户模型,2026-09-06 拍板)

- **池 P** = 哪些目录有 package.xml(快照 `entries` 全量画像:dir/name/buildType/isValid…)。由 package.xml 事件 + 60s 权威维护。
- **标记集 M** = 哪些目录含 `COLCON_IGNORE`。由 60s/懒 walk 全量收集 + `COLCON_IGNORE` 事件增量维护。
- **两路事件正交**:
  - package.xml 事件 = "池里某条目(候选)的派生态可能变了" → **只 walk 重推**(无 colcon);
  - COLCON_IGNORE 事件 = "水桶位置变了" → 只做 **池 × M 纯运算重分类**(把东岸的水舀到西岸),**不 walk 不 colcon**;
  - 60s timer = 双轴全量权威(colcon+walk)。
- **名称空间是工作区级全局不变量**(mergeByName 按 name 去重、unignore 优先、构建按 name 选包、撞名消解):重命名/撞名只能靠**全量重推导**裁决 —— "这个 name 是否还属于你"在只看单目录时无解。→ package.xml(池)事件**不做任何单目录裁决**(不做"内容探测跳过"、不做"局部修补";§12.3/12.4 生效后,原设想的这两类优化**废弃**)。
- **标记本地权威**:COLCON_IGNORE 的增删在本进程内是精确可知的(不像 colcon list 有滞后),故标记事件对 ignore/unignore 的影响可**即时且无扫描**地落地;唯一仍"只加不删、等 60s 收敛"的是**池自身的删除**(目录被删但事件漏发)。

### 12.2 分类规则(纯函数,输入 = 池 entries + 标记集 M + workspaceRoot)

对每条合法池条目 p(=dir 下有合法 package.xml),沿祖先链自根向下找**第一个阻挡者**(镜像 colcon 递归发现的自上而下剪枝时序,不是"离 p 最近"):

| 阻挡者 d | p 的分类 | ignoreReason |
|---|---|---|
| 无 | colcon 可见 → unignore/fallback 候选 | `none`(不设) |
| d == p.dir 且 d ∈ M | 同目录忽略 | `same-dir` |
| d ≠ p.dir,d ∈ M(祖先) | 祖先忽略 | `ancestor` |
| d 为合法包目录(d ≠ p.dir;含"根目录自身是合法包"情形) | 嵌套重叠 | `overlap` |

规则细节:
- 根目录自身若是合法包(单包工作区根),其下所有条目均为 `overlap`(colcon 对 base-path 自身 identify 成功即剪枝整树)——与实测一致;
- 若 p 自身既有同目录标记、上方又有包/标记祖先,按"自根向下第一个阻挡者"判(下方标记不参与,因为 colcon 根本走不到 p);
- `hasColconIgnore`(同目录标记)语义保留,事实源改为 `p.dir ∈ M`(不再每目录 access);
- **派生**:
  - `visible(池)` = 合法 && ignoreReason 为空 → unignore/fallback 的 walk 侧视图(与 colcon 同视图,差异只剩 colcon 独有情形);
  - `unignore 快照` = colconReady ? 合并(colcon 权威名单, 上次权威后新可见的池条目, ~~只加不删~~ → **V3:加 + 交集证据可删,白名单成员常驻,见 §12.12**) : visible(池);
  - `ignore 快照` = 合法条目中 ignoreReason 非空的全部(现含同目录;新增 ancestor / overlap 两类);
  - workspace = unignore + ignore 按 name 去重(不变;同 name 撞名取 unignore,与现状一致);
  - 差异诊断日志口径:colcon list vs visible(池)(ancestor/overlap 不再算"walk 独有",消除 60s 刷屏)。

### 12.10 残余稳定差归因与诊断口径(2026-09-06 22:10)

> 问答结论(用户问"walk 与 list 是否还有稳定差值"):P1/P2 落地后**主干稳定差 = 0**;

### 12.11 讨论记录(2026-09-06 22:10 → 22:28 演化):双圆模型与"目录热排除"(黑白名单对账)

> **演化标注(2026-09-06 22:28)**:本记录中的"回收站"中间态方案**已废弃**(用户自我修正:回收站是为"单次 list 观测留下义务"打的补丁;若 onlylist 只能由同代 pair 认证,中间态即消失);
> 黑/白名单对账核心方向被采纳,精化版 = **V3 候选规格,见 §12.12**。以下为历史讨论全文,供追溯。

> 用户提议(记录):walk 圆 × list 圆,交集不受查询方法影响;list=官方、walk=低成本快速。包可落三区:
> only-walk / only-list / 交集。
> 规则提议:① 执行 list 时把 only-walk 包路径拉入黑名单(ignore);解除仅两途——list 看到它(移入交集)/ walk 不再看到它(出域);
> ② 执行 walk 时"删除" only-list 包(相信其已出域),但**全构建短窗口内双区同时出现 only-list 包 = 铁证**,拉入白名单;
> 出白名单仅一途——list 不再看到它(证明已出域);最长 ≤60s 幽灵时间,接受。
> 后续修正(用户):回收站不必要——全量扫描时快速执行 list+walk,取 onlylist 即为"铁证";回收站理论不完美。

> ② 状态 = 第三种真相源:黑/白名单本身会陈旧(目录删除/改名/复用、followSymlinks/search.excludeFolders 配置翻转、换工作区),需自己的失效与指纹——恰是本轮要消灭的陈旧 bug 的来源;纯"每次读盘推导"变"快照+记忆",不变量与测试复杂化;
> ③ B/C 类其实可无状态消除或属预算伪影,"热排除"用状态修本可用语义修的问题;

> **落地建议(若启用)**:先无状态对齐(B)+归因诊断(A/C/D/E)跑数周统计 onlylist/onlywalk 实际发生次数;残余显著再上"门控学习例外存储"(仅 full+!timedOut 学习;路径键;目录消失/配置变即清;入指纹;原因码并入 ignoredBy 家族);定位=诊断零噪音,正确性仍由 colcon 权威 + 60s 保证,不依赖它。

### 12.12 候选规格 V3:pair 认证 + 快增量(2026-09-06 22:28;用户定稿方向;§12.11 回收站版废弃)

> 一句话:**onlylist/onlywalk 只能由"同 fs 代的 list+walk 对"认证(铁证)**;两次 full 之间 lazy 只做带守卫的快增量
> (**加 + 仅交集证据可删**);无第三态、无回收站。§12 的 P1/P2/B 无状态对齐是 V3 的前提(先清零 onlywalk 稳定类,
> pair 认证才收敛得快);V3 只接管"删得快 + 残余类跨 lazy 存活",**正确性仍由 60s full 托底**。

**认证点(pair)**:full 重建(60s/首建)的 `doRebuild(full)` 内 colcon list → walk **紧邻执行**(近似同 fs 代)。

**三区定义域(先决;用户澄清 2026-09-06 22:33)**:仅 walk 见 / 仅 list 见 / 交集**只定义在"未忽略(unignored)"子集上**——
walk 侧 = `visible(池)`(**没有被忽略的包**:合法 && ignoreReason 空,即不含 same-dir/ancestor/overlap 遮蔽);
list 侧 = colcon list 输出(天然不含被忽略/遮蔽/重叠)。
**深一层理由(用户):忽略包与 list 根本不同论域——list 的定义即"colcon 可见的未忽略包","忽略"= colcon list 补集 ∩ 池,
拿忽略包与 list 做交集是类型错误(无效运算),不是"交集为空";故两圆只能画在未忽略半池上。**
已忽略包(ignore 域成员)不在圆内——它们由水桶语义(池 × M)正交裁决,永远"walk 见而 list 不见"却**不是 walk-only**,绝不因 pair 被扫入黑名单。
⚠️ 若 walk 侧误取为整个池(entries,含 ignore 域成员),全部已忽略包都会落入"仅 walk 见"→ 黑名单污染
(与 ignore 域重复、原因码错乱、lazy 并集抑制误伤);实现与测试必须钉死此定义域。

**认证规则(仅 pair 内成立,定义域 = 未忽略子集)**:

| pair 观测(未忽略子集内) | 分类 | 落点 |
|---|---|---|
| 双见 | 交集成员 | unignore 常规成员 |
| 仅 list 见 | onlylist = 铁证(walk 盲:A 符号链接/C 截断/D 灰度等) | **白名单**(保留在 unignore;下次 pair 由 list 证否才出域;lazy 永不裁决它) |
| 仅 walk 见 | walk-only = 铁证(P1/P2/B 后应 ≈0,剩 D/E) | **黑名单**(不进并集补入;由未忽略转忽略类,原因 = unconfirmed,待下次 pair) |

pair 每次**整体重算**白/黑名单:旧白名单成员若 list 已无 → 出域;旧黑名单成员若 list 已有 → 转交集。
注:ignore 域既有成员(ancestor/overlap/same-dir)由水桶语义维护,**不入白/黑名单、不受 pair 重算影响**。

**状态机转移表(V3 定稿,2026-09-06 22:46;成员身份一律用包目录绝对路径,不用 name)**:

| 事件 | 转移 |
|---|---|
| ignore → 解除(applyMarkerSync 移除标记等) | 落入未忽略 walk 圆,**优先进交集区(unignore/regular),静待下次 pair 发落**(乐观先验:当初被 ignore 是因 colcon 也尊重的阻挡,阻挡没了 colcon 理应看见;pair 证伪再挪) |
| 白名单退出(其一) | ① **成功**的 list 运行一次看不到(≤60s)→ 出域;② **完整(!timedOut)** walk 一次看到(实时)→ 降为 regular |
| 黑名单退出(其一) | ① **完整(!timedOut)** walk 一次看不到(实时)→ 除名(出域/忘掉);② **成功**的 list 运行一次看得到(≤60s)→ **立即移入 unignore(交集区)**;regular/白名单细节留下次 pair |
| regular | walk 不再看到(完整 walk)→ 直接删(快删;交集证据 in place) |
| pair(full) | 整体重算:双见→regular;仅 list→白名单;仅 walk→黑名单;(F,F)→ 无 |

**四条答案(2026-09-06 22:46 用户确认)**:
1. 黑名单成员被成功的 list 看到 → **立即移入交集(unignore)**,理由:list 是官方方法,看到了 = colcon 构建能成功,没理由扣在名单外;
2. 一切 list 驱动的退出/晋级,前提 = **成功的 colcon 运行**(失败 = 看不出,保留旧值,colconReady 语义不变);
3. 一切 walk 驱动的名单变更(白名单"被看到"降级、黑名单"看不到"除名、regular 快删),前提 = **该次 walk 完整(!timedOut)**(注:总超时与分支超时任一触发都会置 timedOut,两者都算不完整;walk 驱动只在 !timedOut 快照上生效);
4. **身份键 = 包目录绝对路径**(= dirname(package.xml)):colcon list 输出、walk entries、事件 dir、白/黑名单四路同构零转换;内部恒绝对、日志可相对;name 只在 workspace 域 mergeByName 展示层去重,**不参与名单身份**——同 name 不同路径 = 两个独立成员。

**lazy(walk 快照)增量规则**:
- 新目录 && ∉ 黑名单 → 并集补入("只加不删"的**加**保留);
- 成员丢失:该成员 ∈ 上次**完整** walk 的 visible 集(交集证据 bit = 1)→ **直接删**;
- 成员丢失但无 walk 证据(白名单成员,walk 本就看不见)→ **不动**,等下次 pair;
- timedOut 的 walk 快照禁止执行任何删/补裁决(见门控)。

**语义账**:

| 场景 | §12(只加不删) | V3 |
|---|---|---|
| 交集包删除 | ≤60s(均值 30s,正幽灵) | **~1s**(lazy 直接删) |
| 白名单(onlylist,如符号链接)包删除 | ≤60s | ≤60s(list 证否,无法更快) |
| 新建普通包 | ~1s | ~1s |
| 新建 onlylist 包(如新加符号链接目录) | ≤60s | ≤60s(walk 看不见,只能等 pair) |

**门控(铁证 → 铁噪防线)**:
1. pair 任一边 timedOut → 本次**不认证**(C 类预算伪影禁止入学);
2. pair 两腿紧邻执行,期间不夹带写盘/大 IO(近似原子;毫秒窗口噪声底,接受);
3. 配置翻转(followSymlinks / search.excludeFolders / walkTimeouts)→ 白/黑名单**作废重学**(follow 开关直接改变 walk 盲区);
4. 白/黑名单**内存态、不落盘**;重启后首个 full pair 重建。
