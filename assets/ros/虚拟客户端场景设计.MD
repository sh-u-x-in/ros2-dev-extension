二、客户端分层设计(VClient 底座不动,加"行为层")
底座 VClient(现状保留):纯协议机器——信封收发/id 匹配/ping/push 收集/串行容忍。
行为层 BehavioralClient(新增,继承 VClient):模拟真实 TS 客户端的行为契约——
- expand(node):get_param_values(按名册全订)+ 记入展开镜像
- collapse(node):镜像移除 + **2 秒定时器**后 unget(真实客户端的防抖语义)
- param push 按展开镜像自动入库(可断言"当前展开的节点收到了什么")
- 自动 resync 沿袭底座
意义:把"真实客户端时序契约"(展开即订/收起 2s 退订/回归不自动重订)整体固化成
可回归的场景,而不是只测单帧。

三、新场景目录(每场景:前置 / 交互 / 预期 / 对应裁定)

C5 ros2cli 临时节点过滤
前置:助手在线,main 已连接
交互:ros2 param set /talker use_sim_time true(瞬时拉起 _ros2cli_<pid> 临时节点)
预期:观察窗口内 graph push 的 nodes/services 均无 _ros2cli 前缀条目;无针对它的
param_structure push;磁盘日志无 _ros2cli 字样(不白烧 wait_for_service)
对应:访问纪律第一条

B10 resync 不清账本
前置:订阅 /talker 全名册(回显确认)
交互:resync → 等 2s → 改 /talker 参数
预期:resync 后仍收到 param push(账本保留);账本回显 resync 前后一致
对应:恢复语义"resync 不清订阅账本"

D7 节点消失清账 + 回归不自动重订阅
前置:订阅 /talker;kill talker(包装+真身)
交互:等 graph push 确认消失 → 重启 talker → 等 graph push 确认回归 → 改参数
预期:回归后改参数,旧连接收不到 param push(账目随节点清,回归不自动重订);
显式重新 get_param_values 后恢复收到
对应:裁定"节点消失即清,回归不自动重订阅"(2026-10-07)

B11 断开清账不泄漏
前置:客户端 A 订阅 /talker;客户端 B 在线但不订阅
交互:A 断开 → 等 1s → 改 /talker 参数
预期:B 零收(A 的账没泄漏成广播);服务端日志出现"账本随连接清"
对应:裁定⑤连接断开只清自己的账

C6 生命周期订阅对账(生死循环)
前置:lc_talker 在线
交互:kill lc_talker → graph push 确认消失 → 重启 lc_talker → graph push 确认回归
→ ros2 lifecycle set configure
预期:回归后的转换仍收到权威 lifecycle push(transition_event 订阅对账重挂成功)
意义:订阅账本生死循环不死记;场景内同步刷新 lc_pid 供后续 D3 组使用

B12 get_form 未知类型错误路径
交互:get_form types=["foo/bar/NoSuch"](不存在的类型)
预期:整条回应 success=false + error 文本(固化现语义=单类型失败整条失败;
若要"好的返回坏的报错"的单类型降级,需服务端改语义,另行裁定)

G1 行为客户端全链路(订阅生命周期编排)
前置:BehavioralClient 连接(名册已随辅助推送到位)
交互:expand(/talker) 收值 → 改参数 → push 送达 → collapse(/talker) →
**2 秒内**改参数 → 仍收到(退订未触发) → 等 2.5s → 改参数 → 不再收到(已退订)
→ re-expand → 改参数 → 收到
预期:六步收/不收精确断言——防抖窗口两侧各验一次
意义:真实客户端时序契约的整链回归

G2 行为客户端 × 重同步
前置:G1 的展开态
交互:resync → 改参数 → push 仍送达
预期:与 B10 互为表里,但走行为层断言(镜像未动则推送照收)

四、不做的场景与原因
- 事件队列背压风暴(1000 上限):无法可靠制造千级参数事件;丢帧自愈=resync 的
  恢复语义已由 B10/G2 覆盖
- 超限帧(20MB):现有 demo 节点无大参数载体,需专用测试节点,超范围
- TS 客户端侧(看门狗/connected 门槛/退避重启):属扩展侧,npm test 域
- 幽灵服务过滤:B2 已有断言,不重复立项
